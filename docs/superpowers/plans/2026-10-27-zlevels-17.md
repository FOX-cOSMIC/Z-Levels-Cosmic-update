# Z-Levels 1.7 Implementation Plan

> **For the implementer:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Port existing Z-Levels to 1.7 and establish actual runtime behavior.

**Architecture:** Preserve subsystem boundaries; use a dedicated 1.7 binary,
SDK-style .NET 10, evidence-driven API migration and isolated game validation.

**Tech Stack:** C#, .NET SDK 10.0.301, RimWorld 1.7.4990, Harmony, PowerShell, ILSpy.

**Spec:** docs/superpowers/specs/2026-10-27-zlevels-17-design.md

## Global Constraints

- Target 1.7.4990 rev1069, not 1.6.
- Preserve gameplay, attribution and historical version folders.
- Separate savedata: existing saves stay unopened and user mod list unchanged.
- Do not ship game assemblies or another Harmony; do not publish.
- Arbitrary modpack/multiplayer compatibility requires separate testing.
- No existing test suite: use builds, target inspection and real-game scenarios.
- Dedicated existing checkout, no new branch authorized, no remote configured.
