Multi-level mods compared

Alu is right about the history of Z-Levels and broadly right about what slows it down. Nobody has measured how bad that slowdown is, in your port or in any other mod. The evidence supports rebuilding one part of your mod, the part that helps a colonist choose their next job. It does not support throwing the whole mod away.

What I found

  • The mod Alu calls Multifloors is MultiFloors by telardo. It has 93,400 subscribers, publishes no source code, and has no official RimWorld 1.7 version.
  • I downloaded it and three of its rivals, turned their compiled files back into readable code, and compared them with your port using the same questions.
  • MultiFloors and Z-Levels both give every floor its own full game map. The biggest difference is that MultiFloors leaves the game's most-used questions alone and looks at the colonist's own floor first. Z-Levels adds checks to those questions and repeats its search on every floor.
  • Your port has been tested hard. Stairs, hauling, mining and building below, power, cooling, and saving have passing test runs. It is still buggy in places: a few test failures have no known cause, and food, rest, fighting, and raids across floors have never been tested.

Each thing Alu said, checked

That one was abandoned
True

The Z-Levels Workshop page says, in the owner's words: "I have abandoned this project and any code that it contains is fair game to anyone who wants to use it." The page's last update was 27 December 2020, for RimWorld 1.1 and 1.2.

It was a commissioned mod and it got very expensive to maintain
Commission is true

RamRod ran the project and paid for the code: "he is the C# programmer, I just hired him." RamRod's Patreon says "I spent a lot of money on C# programming." I found nothing that checks Alu's remark that Taranchuk is the most popular commission coder.

Pathfinding and immense lag
Half proven

Lag. The code proves the work grows with every floor you add, and nothing limits how often it runs. "Immense" is not proven. No report in this repository, and no page I read, gives a measured number for Z-Levels.

Pathfinding. Players did report colonists who could not find routes in 2020. But the mod's big route-finding file, ZPathfinder.cs at 612 lines, is never reached in play, because the one line that would start it is commented out. So it cannot be the source of the lag today.

He wanted the pawns and AI to flow freely between the 2 floors
True, and every rival wants it too

The code shows this goal. Your port kept it, and the job search page shows what it costs. MultiFloors, As Above So Below II, and True Z-Levels all let colonists work across floors. The difference between them is the method.

Multifloors is popular for its stable performance
Popular yes, performance unmeasured

The popularity is real, at 93,400 subscribers against 18,707 for the old Z-Levels. The design has real savings, listed on the next page. Its cost still grows with floors when a colonist has nothing to do. I found no independent speed test.

Part of its speed comes from leaving things out. Its page lists no fighting across floors and says this is "due to considerations of performance and compatibility."

As Above is newer but made by a vibe coder
Newer is true, the label is opinion

The sequel appeared on 2 August this year. Its author says: "This mod is AI assisted. I built it in a full development environment with Claude AI as a coding assistant, and I review, edit and change the code myself." "Vibe coder" is Alu's word, and a decompile cannot show how carefully the author reviewed the code.

The same question applies to your port, where 119 of 122 commits credit Claude. What matters for any of these mods is how they behave when tested.

Deep and Deeper is temp maps so not a full replacement
True by default

Each cave is a separate small map that collapses in about 12 game days if you leave it alone, and sooner if you mine it. A setting turns collapse off. Even then, colonists only cross for mining and hauling, and only if you opt in. It is a mining side trip, not a way to build a second floor.

What this report cannot tell you

  • No mod was run or timed. Everything here comes from reading code and public pages. Which mod is fastest in a real colony is still unknown, and the rebuild page describes the test that would settle it.
  • The rival code is machine-rebuilt. It works for tracing what the code does. Comments are gone, so I did not judge anyone's coding style from it.
  • MultiFloors was read at its 1.6 version. The others were read at 1.7, except Deep And Deeper, also 1.6.
